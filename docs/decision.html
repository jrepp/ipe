Follow one deploy request through IPE

A deploy to production arrives with one approval. The policy requires two. These five steps show what IPE should decide, and where the current build differs.

Evaluate · 1 of 3Integrate · 2 of 3Write policies · 2 of 3
  1. 1

    The request becomes a context

    Your application authenticates the caller and packs the resource, the action, and the request into one Resource–Action–Request context.

    resource  type: Deployment
          environment: "production"
          approvals: 1
action    deploy
request   principal.role: "senior-engineer"
  2. 2

    Policies are selected by resource type

    Both PolicyEngine and PolicyDataStore pick the policies registered for the resource type. The store reads from an immutable snapshot, so a policy update during the request cannot change what this evaluation sees.

    resource type   Deployment
selected        RequireApproval
  3. 3

    The trigger matches

    The resource is a Deployment and production is in the list, so the policy applies.

    Current build: the compiler does not evaluate trigger conditions yet.

    triggers when
  resource.type == "Deployment"       true
  and resource.environment in [...]   true
  4. 4

    The requirement fails

    The caller is a senior engineer, but one approval is fewer than two.

    requires
  resource.approvals >= 2             false
  where request.principal.role == ... true
  5. 5

    The decision, and a known gap

    The policy intends Deny. The current compiler ends every requires policy with Return(true), so the interpreter can return Allow here.

    IntendedDeny
    Current buildAllow
