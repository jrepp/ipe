Project map

Five projects for teams that govern application and agent actions. The connected workflow is planned.

Read the project plan →
Project routes and draft requirements
  • P1

    Policy modeling

    Source → Model → Review → Publish revision

    Policy authors can test a candidate against current facts. The project adds source review before an operator activates the revision.

  • P2

    Evidence integration

    Connect → Observe → Assess evidence → Publish facts

    Collectors retain observations, assessments, and expiry times. The planned handoff publishes approved evidence as runtime facts with the original deadline.

  • P3

    Policy enforcement

    Bind scope → Evaluate → Apply decision → Record outcome

    The runtime evaluates a local snapshot. The project links the result to the application that applied it and the outcome that application observed.

  • P4

    Evidence operations

    Inspect → Time conditions → Temporary authority → Audit

    Previews show policies and evidence. The project connects source and outcome records, then adds time conditions, exceptions, and temporary access grants.

  • P5

    Product site and delivery

    Explain → Validate → Publish

    The site links product claims to guides and draft requirements. GitHub Actions checks the site before it publishes the archive from main.

Current implementation

The runtime and the integration host work separately today.

Evaluate a scoped request

The Rust runtime reads an active policy and local facts from one snapshot. Each fact has an expiry time. The application must block the action after a deny or indeterminate result.
