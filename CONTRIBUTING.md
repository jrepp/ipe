# Contribute to IPE

Start with [QUICKSTART.md](QUICKSTART.md) and the [repository map](docs/REPOSITORY.md).
Choose the owning project in the [project map](docs-cms/PROJECTS.md).
Read its PRD, current implementation guide, source, and tests before editing.

Keep changes within one verifiable outcome. Preserve unrelated work and security boundaries.
Update affected guides when behavior changes. Describe release changes in the PR under the [release process](docs/RELEASES.md).
Record new requirements and proposals in the [design structure](docs-cms/README.md).
Distinguish proposals, sample data, historical results, and implemented behavior.

Run the applicable [validation checks](.agent/validation.md). Report failures and checks that could not run.
Use Conventional Commits. A PR must state the problem, resulting behavior, verification, and remaining limits.
See [merge automation](docs/MERGE_QUEUE.md) for required CI checks and queue activation limits.
